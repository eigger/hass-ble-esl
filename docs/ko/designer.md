# ESL 디자이너

**[English](../designer.md)** | 한국어

> 영어 문서가 기준입니다. 내용이 다르면 [영어 원문](../designer.md)을 따릅니다. 버튼과 필드 이름은 화면에 보이는 영어 그대로 적었습니다.

디자이너는 [`ble_esl.write`](../actions.md) 액션의 **payload**를 눈으로 보면서 만드는 도구입니다. 화면에 보이는 것, 태그로 보내는 것, 내보내는 YAML은 모두 같은 payload이고, 같은 [imagespec](https://github.com/eigger/imagespec) 렌더러가 그립니다. 그래서 여기서 완성한 디자인은 자동화에 그대로 붙여 넣어도 같은 그림이 나옵니다.

Home Assistant 사이드바에서 **ESL Designer**를 엽니다(태그를 하나 이상 설정하면 나타나며, 관리자 전용입니다). 위에서 태그를 고르면 그 태그의 크기와 색으로 캔버스가 만들어집니다.

## 디자인 만들기

| 하려는 일 | 방법 |
|---|---|
| 텍스트, 도형, 아이콘, 이미지 추가 | **Components** 아래의 버튼 |
| 센서 추가 | **Entities**에서 선택: 이름, 값, 아이콘이 요소가 됩니다 |
| imagespec 요소 **아무거나** 추가 | **All elements** → 선택 → **Add**. 서른 가지 모두 있습니다: 도형, 텍스트, QR / 바코드 / 데이터 매트릭스, 차트, 표, 레이아웃 컨테이너, 위젯 |
| 이동, 크기 조절 | 요소나 모서리 핸들을 끕니다. 화살표 키로 1칸, Shift와 함께 10칸 |
| 값 편집 | **Element properties** 패널에 그 타입에서 imagespec이 가진 필드가 모두 나옵니다. 필수는 `*`, 기본값은 placeholder로 표시됩니다 |
| 순서 바꾸기, 복제, 삭제 | **Layers** 목록, 우클릭 메뉴, Ctrl+D, Delete |
| 되돌리기 | Ctrl+Z / Ctrl+Shift+Z. 편집 하나가 한 단계입니다 |

요소의 위치는 직접 입력하는 키가 아니라 **프레임**(X, Y, Width, Height)에서 정해집니다. 사각형은 프레임을 채우고, 원은 프레임 가운데에 놓이고, QR 코드, 바코드, 아이콘은 크기를 프레임에서 받고, 다각형의 꼭짓점은 프레임에 대한 퍼센트입니다. 그래서 모든 요소가 똑같이 움직이고 크기가 바뀌며, 내보낸 payload에는 평범한 절대 좌표가 들어갑니다. 텍스트나 표처럼 자기 크기를 가진 요소는 프레임의 왼쪽 위에서부터 그려집니다.

어떤 값이든 [Jinja 템플릿](https://www.home-assistant.io/docs/configuration/templating/)일 수 있습니다: `{{ states('sensor.room') }} °C`, 목록은 `{{ [1, 2, 3] }}`. 미리보기는 현재 상태로 렌더링하고, 템플릿이 읽는 엔티티가 바뀌면 다시 그립니다. **Auto update sensor**는 디자인이 읽는 값이 바뀔 때 태그를 다시 보냅니다(최대 *interval*초마다). **Send to tag**는 지금 바로 씁니다.

> `plot`은 recorder를 읽으므로 recorder가 있는 Home Assistant가 필요합니다(실제 설치에는 모두 있습니다). 색은 태그가 표시할 수 있는 것으로 제한되며, 그 밖의 색은 가장 가까운 색으로 바뀝니다.

## Payload YAML

**Payload YAML**은 디자인을 imagespec YAML로 보여 줍니다. `payload:` 아래에 붙여 넣을 payload도, 스크립트나 자동화용 완성된 액션(**Automation action** 탭, 이 태그의 `device_id` 포함)도 있습니다.

요소에 템플릿이 있으면 **Keep templates**(기본 켜짐)가 템플릿을 쓴 그대로 둡니다. 그러면 자동화가 실행될 때마다 Home Assistant가 렌더링하므로, 디자이너 없이도 태그가 센서를 따라갑니다. 끄면 지금 값으로 보여 줍니다.

```yaml
action: ble_esl.write
target:
  device_id: 0a1b2c3d…
data:
  background: white
  payload:
    - type: text_fit
      value: '{% set v = states(''sensor.room'') %}{% set n = v|float(none) %}{{ v|capitalize if v in [''unavailable'', ''unknown''] else ((''%.1f''|format(n) if n is not none else v)) ~ '' °C'' }}'
      x: 8
      y: 8
      width: 120
      height: 40
```

지금 값으로 고정되는 것: 기존 센서 컴포넌트([Convert to elements](#convert-to-elements)로 센서를 따라가게 만들 수 있습니다), 필드 템플릿, 꼭짓점이 템플릿인 다각형(꼭짓점은 프레임에 대한 퍼센트라서 렌더링된 텍스트가 있어야 바꿀 수 있습니다). 이 사실과, 렌더러가 거부할 것(알 수 없는 아이콘 등), 자동화에서 Home Assistant가 템플릿으로 읽을 문자열은 텍스트 아래 목록에 표시됩니다.

## Import YAML

**Import YAML**은 이미 가진 액션의 payload를 받습니다. 목록 자체, `payload:`가 있는 매핑, 액션 전체 모두 되고, 각 요소를 편집할 수 있는 요소로 바꿉니다. **Add to display**는 캔버스에 있는 것을 두고 더하고, **Replace display**는 처음부터 다시 시작합니다.

- 디자이너에서 배치할 수 없는 것은 이유와 함께 목록으로 나옵니다: 템플릿이나 스크립트 변수로 계산하는 위치(`x: "{{ grid_x + 10 }}"`), 위치가 없는 요소(앞 요소 다음에 이어서 배치됩니다), 대각선, imagespec에 없는 타입.
- 디자이너는 붙여 넣은 payload와 그것으로 만든 결과를 각각 그려서 **몇 픽셀이 다른지** 알려 줍니다. `0`이면 자동화가 쓰던 것과 똑같이 씁니다. 0보다 크면 디자이너가 무언가를 바꾼 것입니다: 크기가 없던 QR 코드에 프레임이 생겼거나, 꼭짓점이 소수였거나.
- YAML 앵커와 별칭(`&a`, `*a`, `<<: *a`)은 받지 않고, 256 KB를 넘는 텍스트도 받지 않습니다. 반복되는 값은 풀어서 쓰세요.
- 한 디스플레이에는 요소 100개까지 들어가며, 나머지는 목록으로 알려 줍니다.

## Convert to elements

기존 컴포넌트(센서, 텍스트, 아이콘, 이미지, 도형, 진행 바, 게이지)는 디자이너가 가진 설정으로 그려집니다. 속성 패널의 **Convert to elements**는 선택한 컴포넌트를 그것을 그리는 평범한 imagespec 요소들로 바꿔 그 자리에 넣습니다(되돌리기 한 단계). 그러면 각 필드를 편집할 수 있고 YAML도 평범한 imagespec이 됩니다.

값만 표시하는 센서는 값 텍스트가 센서를 따라가는 템플릿이 됩니다. 컴포넌트가 정한 소수 자릿수와 단위가 반영되고, 사용할 수 없는 상태는 이전처럼 표시됩니다. 날씨나 이진 센서, 사용할 수 없는 상태, 단위 없는 숫자만 있는 값(템플릿 결과를 Home Assistant가 다시 숫자로 바꿔서 형식이 사라집니다), 단위 자체가 템플릿 구문인 경우는 이유와 함께 그대로 둡니다.

상태 줄에 결과가 이전과 똑같이 그려지는지(`0` 픽셀 차이), 아니면 얼마나 다른지 표시됩니다.

## 센서 템플릿과 기존 컴포넌트

**Sensor templates**(두 번째 탭)는 센서 종류별로 쓰는 재사용 레이아웃입니다. `{{name}}`, `{{state}}`, `{{unit}}`, `{{icon}}` 자리표시자로 하나를 만들면 그 종류의 모든 센서 컴포넌트가 프레임 크기에 맞춰 그것을 씁니다. 기존 컴포넌트에 속하는 기능이라 imagespec 요소는 넣을 수 없습니다. 센서를 템플릿 체계에서 빼려면 Convert to elements를 쓰세요.

**Configure**는 기존 컴포넌트 자체의 편집기(엔티티, 데이터 필드, 아이콘 규칙, 필드 템플릿)를 엽니다.

## 한계

- 디스플레이당 요소 100개.
- 위치는 프레임에서 나옵니다: 서로 이어서 배치되는 요소(`y` 없음), 대각선, 템플릿으로 계산하는 위치는 배치할 수 없습니다.
- 끌고 있는 레이어는 요소가 그리는 것을 디스플레이에서 오려 낸 것이라, PNG의 부드러운 반투명 가장자리 같은 곳은 끄는 동안 조금 다르게 보일 수 있습니다. 놓았을 때 캔버스에 보이는 그림이 실제입니다.
- 디더링은 디스플레이 전체가 아니라 요소별(`dither:`)입니다. [요소별 디더](../actions.md#per-element-dither-photos--charts)를 보세요.
