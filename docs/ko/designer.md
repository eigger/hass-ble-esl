# ESL 디자이너

**[English](../designer.md)** | 한국어

ESL Manager와 디자이너는 Home Assistant 프로필의 언어 설정을 따릅니다. 컴포넌트와 동일한 13개 언어(영어, 한국어, 독일어, 스페인어, 프랑스어, 이탈리아어, 일본어, 네덜란드어, 폴란드어, 브라질 포르투갈어, 러시아어, 중국어 간체·번체)를 지원합니다. 지역별 언어 코드도 처리하며, 지원하지 않는 언어는 영어로 표시합니다. 언어를 변경해도 미저장 디자인과 열려 있는 편집 창의 입력은 유지됩니다. 기기 별칭, 자동화 이름, 디자인 문구, Jinja 템플릿과 내보낸 YAML은 원문을 유지합니다. 렌더러 문서와 서버 진단 메시지는 원래 언어로 표시합니다.

> 영어 문서가 기준입니다. 내용이 다르면 [영어 원문](../designer.md)을 따릅니다. 문서의 버튼과 필드 이름은 영어 UI를 기준으로 적었습니다.

디자이너는 [`ble_esl.write`](../actions.md) 액션의 **payload**를 눈으로 보면서 만드는 도구입니다. 화면에 보이는 것, 태그로 보내는 것, 내보내는 YAML은 모두 같은 payload이고, 같은 [imagespec](https://github.com/eigger/imagespec) 렌더러가 그립니다. 그래서 여기서 완성한 디자인은 자동화에 그대로 붙여 넣어도 같은 그림이 나옵니다.

Home Assistant 사이드바에서 **ESL Manager**를 엽니다(태그를 하나 이상 설정하면 나타나며, 관리자 전용입니다). 태그 카드에서 **Edit design**을 선택하면 그 태그의 크기와 색으로 캔버스가 만들어집니다.

## ESL 대시보드

ESL Manager는 카드형 대시보드로 시작합니다. 각 카드에는 기존 text 엔티티의 별칭, 기기 이름, 해상도와 색상, 배터리, 동기화 상태, 최근 전송 결과와 소요 시간이 표시됩니다. 별칭이나 상태를 클릭하면 해당 엔티티 상세를 열어 별칭을 수정하거나 전송 에러를 확인할 수 있습니다. 별칭·기기 이름 검색과 에러·미동기화 필터를 제공합니다.

카드의 이미지와 **Last successful send**는 `last_updated_content` 엔티티의 마지막 성공 전송 이미지와 시점입니다. 실패 시에도 이 정보는 유지되고 최근 전송 에러와 소요 시간만 바뀝니다. 동기화는 `display_in_sync` 값이며, 성공 전송 이미지와 미리보기 이미지가 같은지를 나타냅니다. 제공되지 않거나 사용할 수 없는 값은 `—` 또는 알 수 없음으로 표시됩니다.

**Edit design**으로 디자이너를 열고 **Dashboard**로 돌아옵니다. 돌아와도 작성 중인 디자인은 유지됩니다. 디자이너는 수동 전송만 지원하며 센서 변경 시 자동 전송하지 않습니다.


## 현재 디자인으로 자동화 만들기

디자이너 툴바에서 **자동화 만들기**를 선택하고 전송 액션과 이름을 확인한 뒤 대화상자의 **자동화 만들기**를 누릅니다. 저장하지 않은 편집 내용도 포함하며, `ble_esl.write`의 대상은 현재 ESL 기기로 지정됩니다. 실행 조건과 조건 목록은 비어 있으므로 **자동화 편집**에서 언제 실행할지 직접 설정하세요.

생성한 자동화에는 전송 액션의 복사본이 들어갑니다. 일반 디자인 저장은 이 복사본을 바꾸지 않으며, 기존 자동화를 **Edit design**으로 열고 **자동화에 저장**을 누르면 payload를 갱신합니다. imagespec 요소에 작성한 Jinja 템플릿은 보존되어 실행 때 평가되지만, 센서 컴포넌트와 필드 템플릿 값은 **페이로드 YAML**과 마찬가지로 생성 시점의 값입니다. 로컬 데모는 미리보기만 메모리에 저장하며 실제 Home Assistant 자동화를 만들지 않습니다.

## 기존 자동화 연결

카드의 **Automations**를 누르거나 디자이너 위의 **Connected automations**를 누르면 연결 목록이 열립니다. 자동화가 없으면 **Link automation**, 하나면 이름과 상태, 여러 개면 개수와 활성 개수를 카드에 표시합니다. 데스크톱에서는 카드 옆 팝업으로, 모바일에서는 하단 시트로 열립니다. 각 자동화 이름은 HA 편집기로 연결됩니다.

이 ESL의 기기 또는 엔티티를 직접 참조하는 자동화는 자동으로 찾아 표시합니다. 스크립트를 거쳐 참조하거나 템플릿으로 대상이 결정되는 자동화는 기존 자동화를 검색·선택해서 수동 연결할 수 있습니다. 연결은 ESL과 자동화 사이의 관계만 저장하며, 자동화 액션을 수정하거나 디자인을 적용·전송하지 않습니다. 직접 대상을 지정한 기존 액션은 **Edit design**으로 갱신하고, 액션을 수동으로 전달할 때는 **Payload YAML**을 사용하세요.

수동 연결은 **Unlink**로 해제합니다. 직접 참조로 발견한 자동화는 참조가 유지되는 동안 표시되며, 수동 연결도 있는 경우 **Remove manual link**는 수동 연결만 해제합니다. 연결은 재시작과 자동화 엔티티 이름 변경 후에도 유지됩니다. 제거되거나 사용할 수 없는 자동화는 **Unavailable**로 표시하며 수동 연결을 해제할 수 있습니다.

연결된 자동화 옆의 **Edit design**을 선택하면 `ble_esl.write` payload를 별도 편집 세션에서 엽니다. **자동화에 저장**은 최신 설정을 다시 읽어 고유하게 일치하는 액션의 `data.payload`만 바꾸므로 트리거·조건·다른 액션은 보존됩니다. 액션이 바뀌거나 대상이 모호한 경우, 지원하지 않는 대상 또는 유효하지 않은 디자인은 저장을 막습니다. 세션을 나가면 이전 디자인과 실행 취소 기록을 복원합니다. 저장은 Bluetooth 전송을 하지 않습니다.

이 세션에서 자동화 변수는 미리보기 파라미터로 다룹니다. 자동화에 정의된
안전한 리터럴 값은 기본값으로 사용하고, 없는 값은 입력 폼에서 문자·숫자·참/거짓·JSON
타입을 선택해 입력합니다. 문자 값 `fonts/CookieRunBold.ttf`에는 따옴표를 붙이지 않습니다.
가져온 뒤에는 **미리보기 변수**에서 샘플값을 바꿀 수 있습니다. 누락 변수는 값을
직접 입력해야 하며, 빈 문자열을 쓰려면 빈 값 허용 체크박스를 선택합니다. 전체 JSON 편집은
고급 옵션으로 제공합니다. 앞선 자동화 액션이나 서비스 호출은 실행하지 않습니다.
파라미터는 미리보기와 검증에만 사용하며, 저장할 때는 원본 `{{ ... }}` 표현식을
유지합니다. 입력을 취소하거나 렌더링에 실패하면 저장하지 않습니다. 동적 좌표를
파라미터 값으로 고정해서 가져오는 방식은 지원하지 않습니다.

## 디자인 만들기

카드의 **자동화 디자인 편집**은 편집 가능한 연결 자동화가 하나면 바로 열고,
여러 개면 선택 목록을 표시합니다. **디자인 편집**은 일반 로컬 디자인을 엽니다.
편집 화면 상단에는 ESL과 자동화 이름이 표시되고, 좁은 화면에서도 **자동화에 저장**
버튼 문구를 유지합니다.

**배터리 부족** 필터는 기기의 배터리 경고 센서가 켜진 태그를 표시합니다. 정렬 메뉴로
전송 오류·동기화 필요·배터리 경고 순서 또는 배터리 잔량·이름 순서를 선택할 수 있습니다.
**읽기 전용** 태그도 디자인 편집은 가능하지만 전송은 지원하지 않습니다.
미리보기에는 작은 여백을 두고 마지막 전송 성공 이미지를 전체 표시합니다.

자주 사용하는 속성과 필수 속성을 먼저 표시하며, 나머지는 **고급 설정**에서 펼칩니다.
접힌 설정의 값은 그대로 유지합니다.

| 하려는 일 | 방법 |
|---|---|
| 텍스트, 도형, 아이콘, 이미지 추가 | **Components** 아래의 아이콘 버튼 네 개, 한 번 클릭으로 추가합니다. **＋ Add component**는 먼저 컴포넌트 편집기를 열고 센서 값, 진행 바, 게이지, 조건부 아이콘 같은 선택지를 더 줍니다 |
| 센서 추가 | **Entities**에서 선택: 아이콘, 이름, 값을 그리는 센서 컴포넌트 하나가 만들어집니다. **Configure**로 편집하고, [Convert to elements](#convert-to-elements)로 요소들로 나눌 수 있습니다 |
| imagespec 요소 **아무거나** 추가 | **All elements** → 선택 → **Add**. 서른 가지 모두 있습니다: 도형, 텍스트(표와 여러 줄 텍스트 포함), 코드(QR, 바코드, 데이터 매트릭스), 차트, 미디어(아이콘, 이미지), 레이아웃 컨테이너, 위젯 |
| 이동, 크기 조절 | 요소나 모서리 핸들을 끕니다. 화살표 키로 1픽셀, Shift와 함께 10픽셀 |
| 값 편집 | **Element properties** 패널에 그 타입에서 imagespec이 가진 필드가 나옵니다(위치는 프레임이 정하므로 제외, `dither` 추가). 필수는 `*`, 기본값은 placeholder로 표시됩니다 |
| 순서 바꾸기, 복제, 삭제 | 우클릭 → **Send back** / **Bring front**, 복제는 Ctrl+D나 메뉴, 삭제는 Delete나 Backspace 또는 메뉴. **Layers** 목록은 선택용입니다 |
| 되돌리기, 다시 실행 | Ctrl+Z, Ctrl+Shift+Z(또는 Ctrl+Y). Mac은 Ctrl 대신 ⌘. 편집 하나가 한 단계입니다 |

요소의 위치는 직접 입력하는 키가 아니라 **프레임**(X, Y, Width, Height)에서 정해집니다. 사각형은 프레임을 채우고, 원은 프레임 가운데에 놓이고, QR 코드, 바코드, 아이콘은 크기를 프레임에서 받고, 다각형의 꼭짓점은 프레임에 대한 퍼센트입니다. 그래서 모든 요소가 똑같이 움직이고 크기가 바뀌며, 내보낸 payload에는 평범한 절대 좌표가 들어갑니다. `text_fit`과 `new_multiline`은 프레임에 맞춰 그려지고, `rich_text`는 프레임의 가로 중앙선에 놓이며, 선은 프레임 가운데를 지나갑니다(프레임이 가로보다 세로가 길면 세로선). 텍스트나 표처럼 자기 크기를 가진 요소는 프레임의 왼쪽 위에서부터 그려집니다.

어떤 값이든 [Jinja 템플릿](https://www.home-assistant.io/docs/configuration/templating/)일 수 있습니다: `{{ states('sensor.room') }} °C`, 목록은 `{{ [1, 2, 3] }}`. 미리보기는 현재 상태로 렌더링하고, 템플릿이 읽는 엔티티가 바뀌면 다시 그립니다. 디자이너는 센서 값이 바뀌어도 자동 전송하지 않습니다. 내보낸 액션으로 Home Assistant 자동화에서 태그 갱신 시점을 설정하세요. **Send to tag**는 디자인을 저장하고 지금 바로 씁니다.

> `plot`은 recorder를 읽으므로 그 엔티티를 기록하는 recorder가 필요합니다. imagespec 요소가 요청한 색을 태그가 표시할 수 없으면 가장 가까운 색으로 그려지고, 기존 컴포넌트는 태그의 색만 고를 수 있습니다.

완성된 디자인과 작성 방법: [디자인 템플릿](design-templates.md).

## Payload YAML

**Payload YAML**은 디자인을 imagespec YAML로 보여 줍니다. `payload:` 아래에 붙여 넣을 payload도, 스크립트나 자동화용 완성된 액션(**Automation action** 탭, 이 태그의 `device_id` 포함, 쓸 수 있는 태그에서만)도 있습니다.

요소에 템플릿이 있으면 **Keep templates**(기본 켜짐)가 템플릿을 쓴 그대로 둡니다. 그러면 자동화가 실행될 때마다 Home Assistant가 렌더링하므로, 디자이너 없이도 태그가 센서를 따라갑니다. 끄면 지금 값으로 보여 줍니다.

```yaml
action: ble_esl.write
target:
  device_id: 0a1b2c3d…
data:
  background: white
  payload:
    - type: text_fit
      # (다른 키는 생략)
      value: '{% set v = states(''sensor.room'') %}{% set n = v|float(none) %}{{ v|capitalize if v in [''unavailable'', ''unknown''] else ((''%.1f''|format(n) if n is not none else v)) ~ '' °C'' }}'
      x: 8
      y: 8
      width: 120
      height: 40
```

지금 값으로 고정되는 것: 기존 센서 컴포넌트([Convert to elements](#convert-to-elements)로 센서를 따라가게 만들 수 있습니다), 필드 템플릿, 꼭짓점이 템플릿인 다각형(꼭짓점은 프레임에 대한 퍼센트라서 렌더링된 텍스트가 있어야 바꿀 수 있습니다). 무엇이 지금 값인지는 탭 아래 안내문에 나오고, 그 아래 목록에는 렌더러가 거부할 것(알 수 없는 아이콘 등), 지금 값으로 고정된 다각형 꼭짓점, 자동화에서 Home Assistant가 템플릿으로 읽을 문자열이 표시됩니다.

## Import YAML

**Import YAML**은 이미 가진 액션의 payload를 받습니다. 목록 자체, `payload:`가 있는 매핑, 액션 전체 모두 받고, 각 요소를 편집할 수 있는 요소로 바꿉니다. **Add to display**는 캔버스에 있는 것을 두고 더하고, **Replace display**는 처음부터 다시 시작합니다.

- 디자이너에서 배치할 수 없는 것은 이유와 함께 목록으로 나옵니다: 템플릿이나 스크립트 변수로 계산하는 위치(`x: "{{ grid_x + 10 }}"`), 위치가 없는 요소(앞 요소 다음에 이어서 배치됩니다), 대각선, imagespec에 없는 타입.
- 디자이너는 붙여 넣은 payload와 그것으로 만든 결과를 각각 그려서 **몇 픽셀이 다른지** 알려 줍니다. `0`이면 자동화가 쓰던 것과 똑같이 씁니다. 0보다 크면 디자이너가 무언가를 바꾼 것입니다: 크기가 없던 QR 코드에 프레임이 생겼거나(데이터에 따라 차이가 없을 수도 있습니다), 꼭짓점이 소수였거나.
- YAML 앵커와 별칭(`&a`, `*a`, `<<: *a`)은 받지 않고, 256K자를 넘는 텍스트도 받지 않습니다. 반복되는 값은 풀어서 쓰세요.
- 한 디스플레이에는 요소 100개까지 들어가며, 나머지는 목록으로 알려 줍니다.

## Convert to elements

기존 컴포넌트(센서, 텍스트, 아이콘, 이미지, 도형, 진행 바, 게이지)는 디자이너가 가진 설정으로 그려집니다. 속성 패널의 **Convert to elements**는 선택한 컴포넌트를 그것을 그리는 평범한 imagespec 요소들로 바꿔 그 자리에 넣습니다(되돌리기 한 단계). 그러면 각 필드를 편집할 수 있고 YAML도 평범한 imagespec이 됩니다.

속성 패널은 필드를 **Content**(요소가 보여 주거나 연결된 것), **Position & size**(px), **Style**, 접힌 **Advanced**로 묶습니다. 아무것도 선택하지 않으면 디스플레이 **Background**를 정할 수 있습니다. **Layers**의 각 줄은 숨기기(눈), 앞/뒤로 이동, 삭제가 가능합니다. 저장하기 전까지 툴바에 *Unsaved changes*가 표시되고, 저장하지 않은 채 페이지를 떠나면 브라우저가 먼저 묻습니다. 빨간 메시지는 ×로 닫을 수 있습니다.

속성 패널에는 각 요소가 그릴 때 imagespec이 제공하는 선택 설정도 있습니다: 텍스트·센서(세로 정렬, fit, 최대 줄 수, 최소 글자 크기, 패딩, 줄 간격, 글꼴 파일), 도형(채움/윤곽선만, 윤곽선 두께, 모서리 반경), 아이콘(윤곽선 두께·색), 이미지(회전, 원형 자르기), 진행 바(방향, 모서리 반경, 윤곽선 두께, 퍼센트), 게이지(호 두께, 값 표시), 그리고 모든 요소의 **Dither**. 비워 두면 imagespec 기본값이며, **Visible**로 요소를 지우지 않고 숨길 수 있습니다.

값만 표시하는 센서는 값 텍스트가 센서를 따라가는 템플릿이 됩니다. 컴포넌트가 정한 소수 자릿수와 단위가 반영되고, 사용할 수 없는 상태는 이전처럼 표시됩니다.

다음은 그려지던 그대로 텍스트로 남습니다: 날씨나 이진 센서, 지금 사용할 수 없는 센서, 데이터 필드나 필드 템플릿이 있는 센서, 단위 없는 숫자만 있는 값(결과가 숫자뿐인 템플릿은 Home Assistant가 숫자로 읽어서 21.50이 21.5가 됩니다), 따옴표, 역슬래시, 줄바꿈이 든 단위. 마지막 둘은 이유가 표시됩니다. 템플릿 구문이 든 텍스트(`{{`가 들어 있는 단위나 이름)는 imagespec 요소가 되면 Home Assistant가 실행하게 되므로 **결과에서 빠지고**, 이유가 표시됩니다. 픽셀 차이 수가 빠진 만큼을 보여 줍니다.

상태 줄에 결과가 이전과 똑같이 그려지는지(`0` 픽셀 차이), 아니면 얼마나 다른지 표시됩니다.

## 센서 템플릿과 기존 컴포넌트

**Sensor templates**(두 번째 탭)는 센서 종류별로 쓰는 재사용 레이아웃입니다. `{{name}}`, `{{state}}`, `{{unit}}`, `{{icon}}` 자리표시자로 하나를 만들면 그 종류의 모든 센서 컴포넌트가 프레임 크기에 맞춰 그것을 씁니다. 기존 컴포넌트에 속하는 기능이라 imagespec 요소는 넣을 수 없습니다. 센서를 템플릿 체계에서 빼려면 Convert to elements를 쓰세요.

**Configure**는 기존 컴포넌트 자체의 편집기(엔티티, 데이터 필드, 아이콘 규칙, 필드 템플릿)를 엽니다.

## 한계

- 디스플레이당 요소 100개.
- 위치는 프레임에서 나옵니다. **Import**는 서로 이어서 배치되는 요소(`y` 없음), 대각선, 템플릿으로 계산하는 위치를 배치할 수 없습니다. 디자이너 안에서는 필드 템플릿으로 요소를 옮길 수 있습니다.
- 끌고 있는 레이어는 요소가 그리는 것을 디스플레이에서 오려 낸 것이라, PNG의 부드러운 반투명 가장자리 같은 곳은 끄는 동안 조금 다르게 보일 수 있습니다. 놓았을 때 캔버스에 보이는 그림이 실제입니다.
- 디더링은 디스플레이 전체가 아니라 요소별(`dither:`)입니다. [요소별 디더](../actions.md#per-element-dither-photos--charts)를 보세요.
