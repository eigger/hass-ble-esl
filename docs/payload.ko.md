# Payload

[README](../README.ko.md) | [English](payload.md) | **한국어**

## 공통 payload 안내

공통 문법, 요소, 속성, 색상, 회전, 디더링은 [imagespec payload 안내](https://github.com/eigger/imagespec/blob/main/docs/payload.ko.md)를 참고하세요.

## 이 통합에서 payload 사용

개발자 도구 → 동작, 스크립트 또는 자동화에서 `ble_esl.write`나 `ble_esl.write_guarded`를 호출합니다. HA 대상 선택기로 로드된 BLE ESL 기기 또는 해당 기기의 엔티티를 선택하세요. 요소 목록은 `data.payload`에 넣으며 YAML 문자열은 받지 않습니다. `write_guarded`는 중복 억제, 쓰기 잠금, 설정된 디바운스도 적용합니다. 전체 동작과 응답은 [동작 안내](actions.md)를 참고하세요.

HA가 동작 데이터의 Jinja를 먼저 평가한 뒤 등록된 동작 스키마가 목록, 회전, 배경을 검사합니다. 쓰기 파이프라인은 YAML 1.1의 불리언 키를 복원한 후 실제 imagespec 렌더러에 요소를 전달합니다. 요소에는 imagespec 안내에 명시된 속성을 사용하세요. 시각 디자이너의 디자인 문서도 같은 파이프라인으로 컴파일되지만 일반 payload 목록과는 별도 형식입니다.

## 최소 동작 예제

전체 [최소 동작 YAML](../examples/payload/minimal.yaml)을 엽니다. WOLINK 2.9인치 `290` BWRY 태그의 흰색 296 × 128 캔버스에 검정·빨강 사각형을 그립니다. `target.entity_id`를 실제 로드된 BLE ESL 기기의 엔티티로 바꾸세요. 예제 엔티티는 테스트 기기의 이름이며 사용자 환경에 자동 생성되는 값이 아닙니다. [템플릿 동작 YAML](../examples/payload/template.yaml)은 HA 템플릿 평가와 노란 사각형의 90° 캔버스 회전도 보여줍니다.

두 예제는 `dry_run: true`이므로 BLE 전송 없이 미리보기 이미지만 갱신합니다. 기기의 미리보기 이미지를 확인하고 실제 태그에 쓸 때 `dry_run: false`로 바꾸세요. 대상에 설정된 프리셋이 해상도와 팔레트를 결정하므로 먼저 맞는 모델을 선택해야 합니다. 추가 레이아웃과 패널은 기존 [기기 예제](../examples/)를 참고하세요.

## 기기 출력 설정

예제의 WOLINK `290` 프리셋은 296 × 128픽셀과 검정·흰색·빨강·노랑을 사용합니다. 다른 프리셋은 고유 해상도와 BW, BWR 또는 BWRY 팔레트를 사용합니다. 통합 옵션에서 실제 패널과 프로토콜을 선택하세요. 해상도나 색상 모드가 맞지 않으면 실제 출력이 깨질 수 있습니다. 프로토콜 인코딩과 물리적 표시 동작은 기기에 따라 다릅니다.

동작 필드 `rotate`(0, 90, 180, 270)와 `background`로 렌더링을 조절합니다. 통합은 imagespec의 `rotate_mode="canvas"`를 사용하므로 90°/270°에서도 출력 크기가 고정됩니다. 전역 디더링은 비활성화되어 있으며 필요하면 이미지·차트 요소가 지원하는 개별 디더링을 사용하세요. 전역 동작 `dither` 필드는 없습니다.

기본 글꼴은 포함된 `NotoSansKR-Regular.ttf`입니다. 글꼴은 파일명만 사용하여 통합의 포함 글꼴을 먼저 찾고, 다음으로 `/config/www/fonts`(HA 설정 디렉터리의 `www/fonts`)를 찾습니다. [글꼴 및 동작 상세](actions.md)를 참고하세요.

## 지원 기능과 제한

manifest는 `imagespec[datamatrix]>=1.1.0`을 선언합니다. 사용 가능한 요소는 설치된 라이브러리 버전과 문서화된 API를 따릅니다. HA가 동작 데이터 템플릿을 처리하며 imagespec은 준비된 값을 받습니다. 통합은 글꼴 해석기와 로컬 이미지 파일 접근, 지원되는 이력 요소용 recorder 이력을 제공합니다. 이력은 HA recorder가 필요하며 recorder executor에서 조회합니다. 조회가 60초를 넘으면 오류가 발생합니다. 원격 이미지는 HA 호스트에서 네트워크로 접근할 수 있어야 합니다. 경로, 글꼴, URL, 엔티티는 실제 설치 환경에 존재해야 합니다.

예제는 사각형만 사용하므로 이미지 다운로드, 이력, 외부 글꼴 파일이 필요하지 않습니다. 실행 계약은 실제 HA 통합과 등록 동작 스키마를 로드하고 실제 production 렌더러와 설치된 imagespec 공개 렌더러의 결과를 비교하며 BLE 명령은 호출하지 않습니다. 소프트웨어 출력을 검사하며 실제 하드웨어 호환성이나 패널 품질을 보장하지 않습니다. payload 이미지가 로컬 파일과 URL에 접근할 수 있으므로 쓰기 동작은 관리자만 호출할 수 있습니다. 최종 색상은 기기 팔레트로 제한되며 렌더링으로 패널에 없는 색상이나 해상도를 추가할 수 없습니다.

## 문제 해결

먼저 `dry_run: true`로 payload·렌더링 문제와 BLE 전송 문제를 구분하세요. 선택 모델, 로드된 대상, 평가된 템플릿, 팔레트, 글꼴 파일명, 로컬·원격 이미지 접근을 확인하세요. 이력 오류는 recorder 활성화 여부와 요청 엔티티의 이력 존재 여부를 확인하세요. 기기·Bluetooth 실패는 로컬 [문제 해결 안내](troubleshooting.ko.md)를 따르세요. 해결되지 않으면 모델, 펌웨어, 민감 정보를 제거한 동작 YAML과 진단 정보를 기존 [Issues](https://github.com/eigger/hass-ble-esl/issues)에 첨부하세요.
